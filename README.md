#### Selected work

**Research engineering and systems architecture** — translating methods across domains, integrating data and models, and building tools whose assumptions and evidence can be inspected.

- **[Coastal Water Resilience](https://patrickiben.github.io/public-data-consoles/consoles/coastal-water-resilience/)** · [source](https://github.com/patrickiben/public-data-consoles/tree/main/consoles/coastal-water-resilience) — Connects my [CRT framework](https://github.com/patrickiben/crt-design-demo) and [network-contagion research](https://github.com/patrickiben/directed-asymmetry-contagion) to infrastructure planning. Real public station records, terrain, evacuation zones, Census context, and NOAA/NWS observations and forecasts support projected-impact screens and ten-parameter response plans. Actions explain why each parameter matters at that phase, with timing and escalation steps. Unsupported dimensions stay explicit; the synthetic exercise is separately labeled.

- **[Public Data Consoles](https://patrickiben.github.io/public-data-consoles/)** · [source](https://github.com/patrickiben/public-data-consoles) — 32 browser dashboards spanning hazards, healthcare, public health, and markets, including [NHS Scotland Strain](https://patrickiben.github.io/public-data-consoles/consoles/nhs-scotland-strain/), [U.S. Grid Strain](https://patrickiben.github.io/public-data-consoles/consoles/us-grid-strain/), and [River Flood Propagation](https://patrickiben.github.io/public-data-consoles/consoles/river-flood-propagation/). Visitors need no API key. Public feeds and scheduled data publication support dated, source-aware displays; all 32 include ten-parameter response plans with priorities, escalation, and plain-language explanations for public users and professional operators.

- **[Autonomic Telemetry](https://patrickiben.github.io/autonomic-telemetry/)** · [source](https://github.com/patrickiben/autonomic-telemetry) — Wearable sensing from Bluetooth devices through an in-memory Mac bridge to a mobile browser. Work/Rest views combine a personal reference with explicit signal quality, freshness, and source coverage. The [Signal Lab](https://patrickiben.github.io/autonomic-telemetry/Autonomic_Telemetry_Signal_Lab.html) adds replayable numerical views with analytic and regression checks. Live wearable input runs through the local bridge.

- **[Resilience Telemetry](https://patrickiben.github.io/public-data-consoles/consoles/resilience-telemetry/)** · [research guide](https://patrickiben.github.io/public-data-consoles/consoles/resilience-telemetry/wiki.html#s8b) — An application of my directed-contagion research to cross-asset volatility networks: spillover analysis, transmitter stability, historical replay, and held-out comparisons against loudness and persistence baselines. Public-data ingestion and the documented method correspondence make the adaptation inspectable.

#### AI evaluation and grounding

Small, runnable tools for examining model-output reliability and service behavior:

- **[numguard](https://github.com/patrickiben/numguard)** — Deterministic checks of extracted numeric values against allowed facts, required facts, and a finite phrase denylist; JSON/JUnit export for CI.

- **[tool-grounded-agent](https://github.com/patrickiben/tool-grounded-agent)** — A scripted planner demonstrates tool-ledger provenance and a grounding backstop. The harness includes executable known-gap tests; it does not run a language model.

- **[grounded-rag](https://github.com/patrickiben/grounded-rag)** — Lexical retrieval and an extractive answerer with checks for numeric membership and lexical support. A runnable evaluation prototype.

- **[guarded-llm-service](https://github.com/patrickiben/guarded-llm-service)** — The grounding guard served over FastAPI with Docker, CI, and Prometheus-style metrics.
